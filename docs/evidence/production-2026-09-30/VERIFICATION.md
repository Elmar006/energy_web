## Исправления с проверяемым эффектом

| Дефект | Результат |
|---|---|
| UI/BFF создавали синтетический вход без выбора пользователя | Удалён runtime `makeDemo`. Пустое состояние, «—» вместо счётчиков, отключённый запуск. BFF требует ID сохранённого сценария; старый `mode/budget/demand` получает `422` |
| Ошибка нового источника оставляла предыдущий вход на экране | Связь входа с маршрутом и задачей проверяется; предыдущие данные не используются для запуска; ошибка видима |
| Непроверенная HMAC-сессия, смешанные секреты и открытые mutations | Ограниченные сессии, независимый ключ production, обязательный HTTPS Origin, Secure/HttpOnly/Strict cookie, отказ для чужого/отсутствующего Origin, лимит входа и размера тела |
| API принимал токен без Bearer, пустая конфигурация могла совпасть с пустым заголовком | Только непустой настроенный `Bearer`; startup требует явный `APP_ENV` |
| Runtime БД использовал owner | Самостоятельный production Compose, отдельный bootstrap grants; API/worker отвергают привилегированную роль и membership |
| CSV-derived snapshot содержит `demand_dataset: null`, worker ошибочно требует артефакт | `null` означает отсутствие ссылки; снимок передаётся без изменения. Настоящие ссылки проходят SHA-256; повреждённые ссылки и дубли ключей отклоняются |
| Пустые новые поля отказов/переездов меняли SHA старого входа | Пустые additive-поля не меняют историческую идентичность; непустые учитываются. Исторические locks/results не переписаны |
| Уязвимые зависимости | Обновлены `pgx v5.9.2`, `x/text v0.39.0`, FastAPI `0.142.2`, Starlette `1.7.0`, pytest `9.1.1`; тестовые зависимости отделены от runtime |
| Не было проверяемого backup всего входа | Offline dump + архив артефактов + SHA-256, безопасная recovery-проверка в новую БД; повреждение и traversal отклоняются |

## Регрессионный конкурсный эксперимент

Сохранены новые [протокол](protocol_monaco.json), [lock](protocol_monaco.lock.json) и [результат](benchmark_monaco.json), без правки прежних файлов `docs/commission/`. Проверка протокола выполняется до оптимизации. SHA входа `3c1205c8eac01f34b924bfe5f6ef6464c7c3c128ef94f5d8907e4ea364fa8cd3`; SHA исходников engine `76c410c13022ba8816b644f28e35f3735f60e869cdfc3b4828fc7b436f26fc2e`.

Один вход, год 2028, базовый сценарий, **30 одинаковых seed 20001–20030** для всех планов и пяти стресс-условий. Общее время прогона 84,14 с на локальном Python 3.12; MILP `optimal`, gap `0` в загруженной области поиска, независимая математическая проверка прошла.

| План | Средняя обслуженная энергия / спрос | CAPEX горизонта | Сценарный NPV proxy |
|---|---:|---:|---:|
| Существующая сеть | 33,04% | 0 ₽ новых инвестиций | 7,88 млн ₽ |
| Размещение по плотности | 93,29% | 3,70 млн ₽ | 17,54 млн ₽ |
| Оптимизатор | 98,57% | 5,20 млн ₽ | 17,03 млн ₽ |

Парная разность оптимизатора и плотности: **+5,28 п.п.**, 95% модельный bootstrap-интервал **+4,88…+5,67 п.п.** Экономика эвристики выше при меньшем сервисе; это реальный компромисс данной постановки. Не заявляется победа по всем критериям.

Этот прогон **повторно использует ранее закреплённый holdout** и служит регрессией изменённой версии. Он не является новым неизвестным набором для настройки и не подтверждает спрос, тарифы или сетевые условия Monaco. Реальные OSM-координаты с предположенным спросом остаются сценарным кейсом. NPV proxy не является локальной финансовой экспертизой.

## Что не подтверждено этой проверкой

- Внешний HTTPS-ingress, реальная работа Secure cookie через него, доступность тайлов 2ГИС, VPN/SSO и централизованные лимиты на целевом сервере.
- Полный скан OS-слоёв образов/SBOM, удалённый CI, production SLA, off-host хранение и восстановление на масштабе реальных данных.
- Многопользовательский доступ, project RBAC, персональный аудит, S3 и крупные результаты вне PostgreSQL.
- Завершение отдельного Python-процесса при отмене, многопользовательская защита вычислительных ресурсов и постановка долгих задач парков в очередь.
- Реальный операторский holdout, объединение парков с городской инвестиционной моделью и AC-проверка электросети.

Область поставки — усиленная и проверенная основа для **закрытого сценарного пилота**. Условия следующего допуска перечислены в [PRODUCTION.md](../../PRODUCTION.md).
