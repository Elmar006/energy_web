# Статус реализации

Эта страница описывает **код, который действительно запускается**. [README](../README.md) и [PLANS](../PLANS.md) задают полную продуктовую цель; они не являются отчётом о готовности всех возможностей.

## Работает сейчас

- Go API хранит неизменяемые сценарии, хеш входа, расчётные задачи, события и результаты в PostgreSQL/PostGIS. Worker арендует задачи, продлевает lease и публикует результат по attempt ID; отменённая или устаревшая попытка не перезаписывает актуальную.
- Python/HiGHS решает многопериодную задачу размещения для режима города или оператора с общими инвестициями для всех сценариев, годовыми бюджетами, мощностью оборудования, договорным пределом станции, резервом узла, усилением сети, накопителем и PV. В городском режиме при одинаковом покрытии предпочтение отдаётся меньшему времени поездки, затем экономике. Результат содержит статус решателя и gap, если он доступен.
- SimPy моделирует прибытия и очереди для синтетического публичного спроса. Отдельный контрфактический пересчёт показывает влияние удаления выбранной площадки.
- Отдельный расчёт коридора проверяет маршрутный запас энергии, сезонный множитель и отказ любой станции. Отдельная MILP-модель парка назначает зарядку по слотам, учитывая рейсы, SoC, число постов и общий лимит мощности.
- GeoJSON FeatureCollection импортируется транзакционно с проверкой координат и происхождения; GeoJSON и векторные тайлы выдаются из PostGIS. Redis кеширует тайлы, а PostgreSQL остаётся источником задач и результатов.
- Адаптер зарядных сессий CSV строит 24-часовой профиль отпущенной энергии с учётом часового пояса, сохранения энергии и явно заданного окна наблюдений. Входной SHA-256 и источник записываются в манифест нового `PlanningInput`; зоны без наблюдений не заполняются нулями. По умолчанию CSV помечен как предположение, `observed` указывается только явно.
- CLI-адаптер сетевого резерва принимает полный почасовой CSV для каждого узла, отклоняет неизвестные узлы, пропуски, дубли и отрицательные значения, записывает источник и хеш. При тестировании синтетического CSV его можно пометить `assumed`; метка `observed` остается заявлением поставщика, не независимым подтверждением.
- CLI-адаптер OSRM строит матрицу достижимости и времени поездки на основе выбранного пользователем автомобильного OSM-графа. Проверяются недостижимые пары, лимит времени и удалённость координат от дорожного графа; происхождение графа и хеш ответов добавляются в манифест. В Compose есть необязательный профиль `routing`, требующий заранее подготовленного графа.
- Next.js предоставляет локальный интерфейс со сценарием, Яндекс Картой при наличии ключа JavaScript API, расчётом, показателями, этапами и объяснениями. Пользователь может загрузить собственный `PlanningInput` JSON: Python проверяет контракт до сохранения, PostgreSQL хранит неизменяемый снимок, интерфейс открывает его повторно и использует его площадки, зоны и годы. Без ключа карты нет, но расчёты работают. Весь встроенный демонстрационный спрос и энергетические данные являются предположениями.
- OpenAPI 3.1 генерируется в [openapi.json](../openapi.json) из схемы расчётного входа и публичных маршрутов.

## Пока не реализовано

- Автоматическое скачивание, версионирование и регулярное обновление OSM-экстрактов; H3-иерархия и масштабируемый кэш дорожных матриц. OSRM сейчас вызывается отдельным воспроизводимым CLI-шагом.
- Автоматическое превращение импортированных GeoJSON-слоёв в согласованный расчётный вход. Сейчас пользователь загружает полный `PlanningInput` отдельно.
- Импорт GTFS, связывание рейсов с машинами, зарядные кривые и перегоны; текущая модель парка принимает уже нормализованные рейсы и окна.
- Прогнозирование CatBoost, калибровка спроса на наблюдениях, статистическая проверка переноса модели на другой город.
- Оценка латентного спроса, который не наблюдается в выполненных зарядных сессиях. Нынешний CSV-адаптер выводит только профиль фактически отпущенной энергии.
- Автоматическая сверка пользовательского происхождения данных с первоисточником, полная полевая provenance-модель, сезонные/многолетние реальные профили сетевого резерва и официальный процесс проверки условий присоединения.
- Полная электрическая схема и AC power-flow в pandapower. Проверяются лимиты подключения и узла, но результат не является заключением о режиме сети.
- CVaR, адаптивные решения после наблюдения сценария, набор недоминируемых альтернатив и бенчмарки против эвристик.
- Эксплуатационный диспетчер накопителя и PV в SimPy: оптимизация их учитывает, симуляция пока не подтверждает их фактический диспетчерский эффект.
- Многопользовательские проекты/RBAC, внешнее S3-хранилище, производственный провайдер аутентификации, отчёты PDF и отказоустойчивые контрольные точки решателя.

## Границы интерпретации

NPV в текущем ядре вычисляется из представительных суток, умноженных на 365, и заданных тарифов/затрат. Это сценарная экономика, не инвестиционное заключение. Годы должны быть последовательными. Синтетический пилот на координатах Екатеринбурга не подтверждает фактический спрос или доступную сетевую мощность города. Результат `optimal` относится только к переданному набору кандидатов и временной дискретизации.

Текущая аутентификация фронтенда — общий демонстрационный пароль. Она подходит для локального пилота, но **не** реализует проектные роли и разграничение пользователей. Все вошедшие видят сохранённые сценарии; не загружайте конфиденциальные реальные наборы в многопользовательское окружение до реализации RBAC. Публичный Go API использует статический bearer token; перед внешней эксплуатацией потребуются полноценная аутентификация, авторизация и TLS. Пометка `observed` в пользовательском JSON пока не подтверждается независимой сверкой с источником.
