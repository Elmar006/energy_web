# Матрица возможностей и технических ограничений

Документ описывает действующее поведение Энергоконтура. Публичные поля определяются [OpenAPI](../openapi.json), конфигурация запуска — [RunSpec](CALCULATIONS.md#runspec). Запланированная возможность не считается реализованной по наличию интерфейса или текста в документации.

## Что модель означает

Датированные заявки и средний профиль — разные основания спроса. История зарядок не содержит пользователей, которые не смогли зарядиться. Поездки охватывают предоставленную выборку; её репрезентативность не оценивается автоматически. `observed` — заявление поставщика о происхождении, пока источник не проверен отдельно.

`optimal` относится к конечному набору кандидатов, вариантов оборудования и почасовой сетке. Даже `verification.passed` и `accepted` не подтверждают истинность входного спроса или резерва сети. Аудит и симулятор имеют отдельную логику, но входят в тот же программный пакет.

Экономика задаётся ценами входа: legacy-профиль экстраполируется на 365 дней; календарный период — через явный `annualization_factor` с основанием `assumed_repeat`. Это NPV сценария. Сезонный год и местные инвестиционные параметры должны подтверждаться отдельно.

## Незакрытые ограничения

| Область | Недостающая возможность | Условие закрытия |
|---|---|---|
| Городские данные | Независимая история, условия присоединения, местные цены, полевая provenance/сверка источников | Российский кейс с источниками, отложенным периодом и диапазонами неизвестных параметров |
| Общий транспортный план | Парк и публичная сеть сейчас отдельные; рейсы не делят городской инвестиционный бюджет/посты | Единая ресурсная модель без двойного использования поста, узла и бюджета |
| Активы и время | Один комплект на площадке, фиксированная существующая конфигурация; нет общего 15-минутного инвестиционного MILP | Расширение инвентаря, смешанные типы, точные окна и независимая проверка конфликтов |
| Электрический режим | Нет pandapower/AC, параметров линий и напряжений | Полная схема сети и отдельный power-flow отчёт; без схемы — только лимиты |
| Сезон / износ | Короткий период, нет подтверждённого сезонного года и подробной долгосрочной деградации | Последовательный репрезентативный период, корректные границы энергии и расходы износа |
| Улучшение плана | До нескольких вариантов с закреплением дополнительных площадок, а не универсальная генерация ограничений | Исправление заданных классов нарушений в бюджете, история итераций и независимая финальная проверка |
| Альтернативы / эффект | Нет полного доказанного фронта Парето и сравнения затрат при одинаковом сервисе | Предопределённый протокол, недоминируемые планы, равный сервис и сравнение жизненного цикла |
| Масштаб | Нет H3/иерархии, версионируемого route cache и серии территорий с памятью/временем | Минимум три размера и другая территория; область поиска, gap, стенд и профилирование |
| Доступ | Общий пароль экземпляра, все вошедшие видят общие данные | Проекты, пользователи, RBAC и проверка принадлежности на каждом маршруте |
| Артефакты | Local store для входов; крупные результаты в БД и усечение аудита до 2000 строк с флагом | Local/S3 для крупных результатов, контроль доступа и полные хешируемые аудиты |
| Вычислительный процесс | Нет отдельного управляемого subprocess/checkpoints; парк синхронный | Queue для парка, лимиты памяти/времени и принудительная остановка solver при отмене |
| Подключения источников | OSM/OSRM/GTFS — явные подготовительные CLI; универсального произвольного OSM importer нет | Проверяемые адаптеры, обновления и явные версии дорожного графа/слоёв |
| Прогноз | Нет CatBoost и независимой калибровки вероятностей | История, временная проверка без утечки и выигрыш над сезонной baseline |

Production-профиль **уже разделяет owner и runtime роли**: owner есть только у одноразовых migrate/runtime-role этапов, API/worker проверяют ограниченные привилегии. Это не RBAC пользователей. Отмена **защищает публикацию**; она пока не гарантирует немедленную остановку вычислений Python.
