# Визуальная система рабочего пространства

Актуально на 1 октября 2026 года. Реализация: `frontend/src/app/engineering.css`, базовые цвета и радиусы — `globals.css`. Это спецификация существующего интерфейса, а не макет будущих функций.

## Направление

Сдержанный монохромный инженерный продукт: чёрная навигация, светлое рабочее поле, выразительная типографика и минимум декоративных элементов. Основной пользователь — аналитик, который готовит вход, рассчитывает размещение и проверяет результат. Главное действие страницы соответствует текущему этапу работы.

Рассмотрены три композиции: рабочее пространство с боковой навигацией, редактор с верхней навигацией и плотная техническая консоль. Выбрана первая: она сохраняет знакомую структуру, даёт место карте и таблицам, допускает выразительный стартовый экран. Маркетинговые карточки, декоративные градиенты и цветные акценты для оформления не используются. Исключение — предоставленный знак `brand-logo.png`: он сохраняет исходный бирюзовый цвет. Название и путь знака задаёт `frontend/src/lib/brand.ts`; интерфейс, favicon и README используют одну идентичность «Энергоконтур».

## Токены

| Назначение | Значение |
|---|---|
| Рабочий фон / поверхность | `--page: #f6f6f6` / `--surface: #ffffff` |
| Навигация / основное действие | `--surface-header: #0b0b0b` / `--accent: #111111` |
| Основной / вспомогательный текст | `--text: #000000` / `--muted: #4a4a4a` |
| Структурные границы / контур поля | `--border: #e2e2e2` / `--control-border: #858585` |
| Радиусы: поле / группа / панель | 8 / 12 / 16 px |
| Отступы | 4, 8, 12, 16, 20, 24, 32, 40, 48, 64 px |
| Основной шрифт | Локальный IBM Plex Sans: поля, подписи, таблицы и показатели; веса 400, 500, 600 |
| Заголовки | Локальный Manrope; веса 500 и 600, отдельный токен `--font-heading` |
| Типографика | Метаданные 12, подписи 13, основной текст 14, разделы 20, заголовок страницы 36 px |
| Основные показатели / стартовый заголовок | 32 / 40 px; на телефоне 28 / 32 px |
| Элементы управления | Основная высота 44 px; табличные элементы 40 px |
| Движение | Переходы 180 ms; отключаются при `prefers-reduced-motion` |

Числа таблиц и показателей используют табличные цифры. IBM Plex Sans выбран за технический рисунок букв и читаемые подписи; Manrope отделяет заголовки от данных. Рассмотрены прежний Onest, пара Plex/Manrope и единая семья Plex. Выбрана пара: она даёт заметную иерархию без декоративного шрифта или моноширинного основного текста. Цвета ошибок сохраняют предметное значение; статусы всегда подписаны словами. Светлая тема с тёмной навигацией является единственной поставляемой темой, переключатель тёмной темы не заявляется.

Оба файла поставляются через `next/font/local`; запросы к внешнему сервису шрифтов не нужны ни браузеру, ни сборке. Исходные файлы, лицензии OFL и закреплённые ссылки с SHA-256 — в `frontend/src/app/fonts/`. IBM Plex Sans: ось веса 100–700; Manrope: 200–800. Проверены кириллица, латиница, цифры и отображаемые символы единиц. Моноширинный системный шрифт остаётся только в JSON и хешах.

## Композиция и адаптация

- Пустое планирование: сначала законченный стартовый блок с подготовкой данных, затем импорт готового JSON и недоступный запуск. Схема сети — явно подписанная декоративная иллюстрация; она не отображает площадки, узлы или расчётные числа.
- План с входом: панель условий слева, предметное представление справа. Список файлов и хеши раскрываются отдельно, происхождение данных остаётся видно сразу.
- Редакторы: отдельные группы параметров, единые подписи и поля; экспертный JSON в раскрывающемся блоке. Внешний контейнер страницы не создаёт дополнительную карточку вокруг каждой формы.
- Результаты: акцент на основной метрике, затем остальные показатели, таблицы и объяснения. Контекст года и сценария остаётся явным.
- При ширине менее 1024 px боковая навигация становится верхней. На телефоне все четыре раздела видны одновременно: «План», «Данные», «Поездки», «Модели».
- Семь представлений результата показываются целиком: одним рядом на широком экране, двумя рядами на узком. Полные доступные имена сохраняются, даже когда видимая подпись сокращена.
- Большие таблицы прокручиваются внутри своей области. Документ не должен расширяться на ширинах 320–1440 px.

## Компоненты и состояния

| Компонент | Контракт |
|---|---|
| `primary-button` | Одно основное действие: чёрная заливка, белый текст; hover, active, focus, disabled |
| `secondary-button` | Вспомогательное действие: светлая поверхность, спокойный контур |
| `Select` | Именованный combobox, стрелки / Enter / Escape, возврат фокуса |
| `SectionTabs` | `id`, `label`, необязательный `compactLabel`; полное имя в ARIA, стрелки / Home / End |
| `ObjectTable` | Общий редактор строк, связей и удаления с восстановлением; сериализация дополнительных полей сохранена |
| `PlanningEmpty` | Подготовка входа без автоматически созданных данных |
| `NetworkFigure` | Общая SVG-иллюстрация входа и стартового экрана; скрыта от скринридера |

Загрузка сохранённого расчёта имеет отдельное состояние и не выдаётся за отсутствие данных. Ошибки, пустые таблицы и недоступные действия используют тот же набор токенов. Кнопки-ссылки не имеют текстового подчёркивания; ссылки на объекты в таблице сохраняют узнаваемое подчёркивание.

## Тексты интерфейса

Заголовки обозначают текущую задачу: «Планирование», «Данные», «Спрос», «Парк», «Коридор». Дополнительная строка, повторяющая назначение приложения, не добавляется. Действия называются глаголами: «Войти», «Добавить данные», «Сохранить версию», «Рассчитать план». Номер модели, год, единицы и выбранная версия остаются рядом с соответствующими данными.

Пояснение нужно, если оно предотвращает ошибку: CSV требует сценария, время парков задаётся интервалами, история сессий не описывает весь спрос, проверка формата не подтверждает источник. Эти условия сохраняются. Слоганы, повтор названия продукта, «рабочие инструменты», «проверяемое решение» и объяснение очевидного назначения страницы удалены. Слова «контракт» и «вход» в обычных действиях заменены на «параметры» и «данные»; имена API-схем сохранены в экспертном JSON.

## Проверка и границы

Браузерные проверки охватывают страницы, представления результата, клавиатуру, размеры целей и основные контрастные пары. Контуры полей проверяются отдельно от декоративных границ панелей. Линтер, TypeScript и производственная сборка обязательны после изменений.

Фактические результаты прогона и снимки — в [описании поставки](ENGINEERING_UI_IMPLEMENTATION.md); изменение шрифтов и текстов — в [протоколе типографики](ui-2026-10-01-typography/verification.md). Пользовательские испытания на инженерах, проверка внешним скринридером и сертификация WCAG не проведены. Оставшийся глобальный CSS содержит исторические стили: новые экраны развиваются через общие токены и компоненты, а не отдельные наборы оформления на каждой странице.
