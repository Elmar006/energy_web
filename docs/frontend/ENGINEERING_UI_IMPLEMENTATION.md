# Веб-интерфейс: маршруты, состояние и компоненты

Энергоконтур, Next.js App Router. Это техническое описание реализованного клиента. HTTP-контракт — [BACKEND_HANDOFF.md](BACKEND_HANDOFF.md), визуальные токены — [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md).

## Навигация

| URL | Назначение |
|---|---|
| `/login` | Вход с сохранением исходного адреса в `next` |
| `/plan` | Источник, параметры и запуск городского плана |
| `/runs/[id]` | Состояние сохранённой задачи и восстановление результата |
| `/data/scenario` | Редактор/импорт полного PlanningInput |
| `/data/csv/sessions`, `/data/csv/grid` | Исходные CSV, происхождение, покрытие и новая версия сценария |
| `/data/geo` | Нормализованный GeoJSON и сборка из выбранных версий |
| `/data/dated` | Календарь, датированные заявки и ссылка на артефакт |
| `/mobility` | Поездки/стоянки и производный потенциальный спрос |
| `/models/fleet`, `/models/corridor` | Отдельные модели парка и коридора |

Источник передаётся как `?scenario=<uuid>`. Переходы через `Link` сохраняют `WorkspaceProvider`. `/runs/[id]` восстанавливает расчёт по ID, поэтому результат не зависит от сохранённой вкладки браузера. Городские параметры присутствуют только в планировании. Парк и коридор не являются вкладками единого городского инвестиционного расчёта.

## Состояние и происхождение

- Без источника показано «Данные не загружены», действие загрузки и недоступный запуск. Счётчиков вымышленных площадок/узлов нет. Декоративная SVG-схема явно подписана иллюстрацией.
- Источник должен совпадать с текущим URL и входом задачи. При ошибке нового источника предыдущий снимок не используется для расчёта.
- Пользовательский JSON валидируется до сохранения. Импорт меняет версию, а не модифицирует сохранённый сценарий.
- Метки observed/derived/assumed и источник остаются видимыми; список SHA раскрывается отдельно. Отсутствующее значение показывается как «—», а не ноль.
- API/solver/service статусы раздельны. Пустой допустимый план, infeasible, rejected и inconclusive имеют собственный смысл; зелёное выполнение задания не означает принятие плана.
- Редактирование отдельной модели снимает предыдущий результат. Удаление строки можно отменить; экспертные поля JSON сохраняются при табличном редактировании.

## Представления результата

| Представление | Данные и ограничения |
|---|---|
| Сводка | Обслуживание оптимизатора, NPV за весь горизонт, ожидание симуляции, выбранные объекты; год и сценарий указаны явно |
| Территория | Карта 2ГИС, реестр и инспектор площадки; таблица работает без картографической подложки |
| Эксплуатация | Посуточные метрики, станции, очередь и обслуживание; число прогонов не скрывается |
| Энергетика | Проверка лимитов, энергобаланс, SoC и аудит; не AC-режим |
| Экономика | Сценарные инвестиции/денежные потоки; неподтверждённые цены не становятся местной оценкой |
| Сравнение | Сохранённые альтернативы, различия сервиса/стоимости и контрфактический расчёт |
| Данные и протокол | Версии, источники, допущения, RunSpec, fingerprint и JSON-экспорт |

На телефоне параметры после расчёта сворачиваются. Все четыре раздела навигации и семь представлений результата остаются доступными. Внутренние таблицы имеют собственную прокрутку; документ не расширяется на проверенных 320–1440 px.

## Компоненты и ответственность

| Код | Ответственность |
|---|---|
| `src/components/workspace/workspace-state.tsx` | Источник, сессия, состояние запуска/результата и связь с маршрутом |
| `src/components/workspace/planning-view.tsx` | Представления расчёта и состояния результата |
| `src/components/workspace/territory.tsx` | Поиск и инспектор площадок |
| `src/components/workbench-*.tsx` | Предметные формы загрузки и отдельных моделей |
| `src/components/ui/object-table.tsx` | Табличное редактирование, восстановление строки, сохранение неизвестных полей |
| `src/components/ui/section-tabs.tsx` | Полные ARIA-имена, компактные подписи, стрелки/Home/End |
| `src/components/ui/select.tsx` | Combobox, выбор клавиатурой и возврат фокуса |
| `src/lib/brand.ts` | Название «Энергоконтур», описание, единый путь логотипа |
| `src/app/layout.tsx` | Провайдер, локальные шрифты, русская metadata и favicon |
| `src/app/api`, `runtime` | BFF, HMAC-сессия, Origin, лимиты тела; серверный API_TOKEN не попадает в браузер |

Логотип — неизменённый `frontend/public/brand-logo.png`, тот же знак, что в README. Бирюзовый цвет используется только в предоставленном знаке; интерфейс остаётся монохромным. Локальные IBM Plex Sans/Manrope, OFL и SHA исходников описаны в [каталоге шрифтов](../../frontend/src/app/fonts/README.md).

## Проверка и сопровождение

```sh
cd frontend
npm test
npm run lint
npm run typecheck
npm run build
APP_ACCESS_PASSWORD='<действующий пароль экземпляра>' npm run test:e2e -- --workers=2
```

В PowerShell задавайте пароль через `$env:APP_ACCESS_PASSWORD`. Значение должно соответствовать **разрешённой конфигурации запущенного Compose**, а не буквальному `${...}` из `.env`. `ENERGY_FRONTEND_URL` меняет адрес стенда, `ENERGY_CHROME_PATH` — путь локального Chrome. Сквозные тесты создают тестовые сценарии в локальной БД; не направляйте их на экземпляр с операторскими данными.

Часть тестов использует контролируемые API/SDK для состояний формы и карты. Сквозной импорт/расчёт выполняется настоящими Go API, worker, engine и PostgreSQL. Проверка SDK не подтверждает доступность внешних тайлов. Проверки фокуса и контрастов не заменяют ручной аудит экранного диктора.

Текущая поставка: [проверка 1 октября](../evidence/task-fit-2026-10-01/VERIFICATION.md). Предыдущие версии UI имеют собственные неизменяемые протоколы: [компоновка](ui-2026-10-01/verification.md), [типографика](ui-2026-10-01-typography/verification.md). Их снимки не описывают текущее название; они сохраняются как доказательства своих изменений.
