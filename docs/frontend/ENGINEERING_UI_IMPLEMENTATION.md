# Инженерное рабочее пространство

Дата проверки: 30 сентября 2026 года. Репозиторий: `E:\energy`, ветка `backend/algo`.

Эта поставка изменяет интерфейс и его клиентское состояние. Исторические эксперименты и физические формулы не переписываются. Убраны автоматические демовходы; дополнительная подготовка BFF/Compose и новый регрессионный протокол описаны в [PRODUCTION.md](../PRODUCTION.md). Источник требований — [аудит предыдущего интерфейса](ENGINEERING_UI_AUDIT.md), фактический [контракт бэкенда](BACKEND_HANDOFF.md) и пользовательская задача создать понятный инженерный инструмент.

## Пользовательский поток

**Источник → подготовка входа → запуск → проверка результата → сравнение → экспорт.**

Постоянная навигация содержит четыре направления: планирование, данные, маршруты и отдельные модели. В каждой странице свой заголовок и основное действие. Источник выбирается один раз в шапке; смена источника сохраняет текущий раздел. Переход со старого результата на новый источник открывает планирование. Боковая панель городского расчёта присутствует только в планировании.

На мобильном экране после получения результата параметры сворачиваются. Кнопка «Развернуть» возвращает полный набор условий; значения сохраняются. На десктопе условия видны постоянно.

## Реализованные представления

| Представление | Содержание и область показателей |
|---|---|
| Сводка | MILP-обслуживание выбранного года и сценария, число площадок, NPV всего горизонта, среднее seed-p95 ожидания, три независимых статуса, этапы строительства |
| Территория | Карта, поиск и реестр площадок, выбор объекта, инспектор подключения и происхождения, объяснение пересчётом без объекта |
| Эксплуатация | Распределение симуляций выбранного года/сценария, приёмка по условиям, посуточная работа |
| Энергетика | Проверка физических ограничений и подробные потоки выбранного года/сценария |
| Экономика | CAPEX по календарным годам и сценарный NPV после симуляции; годовой фильтр не превращает NPV горизонта в годовую оценку |
| Сравнение | Основной план и альтернативы при одном входе; CAPEX всего, обслуживание и разрыв модели с симуляцией для выбранного года/сценария; подробности раскрываются по варианту |
| Данные и протокол | Происхождение входа, предупреждения, SHA-256, параметры запуска и отдельные статусы задачи, модели и сервиса |

Если результат ещё не рассчитан, соответствующее представление сообщает условие появления данных. Отсутствующий показатель выводится как «—». Большие таблицы прокручиваются внутри своих разделов, не расширяя документ. Вкладки доступны стрелками, Home и End.

**Экспорт JSON:** файл `energy-run-<id>.json`, оболочка `schema_version=workspace-export-v1`, поля `run`, `result`, `scenario`. Это клиентский снимок открытого результата. Он не заменяет серверные артефакты и не обещает отдельную криптографическую подпись файла.

## Ввод данных

- Коридор: характеристики автомобиля с SoC в процентах, длина и расход, таблица станций с доступностью. Результат показывает достижимость, участки и последствия отказов.
- Парк: таблицы машин, постов, рейсов и окон зарядки; машины и площадки в связанных строках выбираются из списка. Проценты КПД переводятся в доли перед отправкой. Результат показывает расписание, пик, число обеспеченных рейсов и конечную энергию.
- Табличный редактор сохраняет дополнительные поля, переданные через экспертный JSON. Удалённую строку можно восстановить; изменение параметров убирает предыдущий результат модели.
- Календарь: даты выбираются через календарный ввод, удаляются отдельными кнопками; пропуски в последовательности явно обозначены. Контрактный предел — 14 дней.
- CSV: требование выбрать сохранённый сценарий видно до заполнения формы.
- Геоданные: выбор версии подписан предметным названием. Ошибки API раскрывают поле и причину, если сервер вернул структурированную диагностику.

Парк и коридор остаются самостоятельными расчётами; интерфейс прямо сообщает, что их ресурсы не объединены с городским инвестиционным планом.

## Состояние и защита от смешивания входов

Без явно выбранного сценария мощности, площадки, спрос, годы и цены не подставляются. На пустом `/plan` значения показаны как «—», запуск отключён. Ошибка загрузки нового источника явно показана и не открывает прежний вход. [Фактический пустой экран](ui-2026-09-30/empty-production-input.png).

Выбор сценария и адрес расчёта синхронизируются с маршрутом. Ответы предыдущей загрузки не могут заменить более новый выбор; запоздавшие ответы расчёта игнорируются после изменения контекста. Загрузка нового сценария со страницы результата больше не возвращает прежний run. Регрессия проверяется последовательным расчётом допустимого и несовместимого CVaR-входа через реальные сервисы.

## Визуальная система

Чёрно-белая тема: тёмная навигация, светлая рабочая область, спокойные границы и один акцент на активном действии. Шрифт хранится локально. Новые элементы используют общую шкалу отступов, размеров текста и радиусов; функциональные размеры таблиц, карты и панелей задаются отдельно. Статусы сообщаются текстом, не только цветом. Фокус заметен на светлом и тёмном фоне.

Снимки фактического интерфейса: [сводка](ui-2026-09-30/overview-desktop.png), [сравнение](ui-2026-09-30/comparison-desktop.png), [мобильная сводка](ui-2026-09-30/overview-mobile.png), [редактор парка](ui-2026-09-30/fleet-desktop.png). На снимках открыт сохранённый **синтетический** пример; отображённые числа не являются доказательством точности для города.

## Проверка поставки

Проверены `npm run lint`, `npm run typecheck`, производственная сборка и запуск Compose. Итоговый браузерный прогон: **22 теста прошли**, время — 59,5 секунды. Браузерный комплект включает:

1. Девять рабочих URL на шести ширинах: 1440, 1280, 1024, 968, 390 и 320 px.
2. Все семь представлений рассчитанного результата на этих ширинах; отсутствие горизонтального переполнения документа.
3. Навигацию и сохранение параметров между разделами; клавиатуру вкладок и списка источников.
4. Поиск и инспектор площадки при отключённой карте.
5. Передачу данных табличных форм коридора и парка, проценты/доли, связи, сохранение дополнительных полей, восстановление строки и сброс устаревшего результата.
6. Даты календаря и разрывы покрытия.
7. Реальный путь вход → импорт → Go API → worker → Python → сохранённый результат, обновление страницы, JSON-экспорт и выход.
8. Импорт Monaco и отображение сравнения, энергетики, эксплуатации и качества входа.
9. Допустимый CVaR-вход и последующий несовместимый вход без выдачи старого результата за новый план.
10. Контраст основных текстовых пар ≥4,5:1 и границ полей ≥3:1, видимый фокус и закрытие списка Escape.

Тесты форм/компоновки используют контролируемые ответы; тесты планирования обращаются к локальным сервисам. SDK 2ГИС в отдельном тесте подменяется: проверены маркеры и управление масштабом, доступность внешних тайлов не подтверждена. Полный аудит WCAG с внешним скринридером и пользовательское исследование не проводились.

## Следующая работа для фронтенда

Сложные редакторы полного сценария, маршрутов/активностей, датированных заявок и детального оборудования ещё содержат экспертный JSON. Эта поставка не закрывает весь продуктовый редактор предметной модели. Следующие расширения должны использовать фактический контракт, сохранять дополнительные поля и проверять единицы при сериализации.

Нужны предметные редакторы этих сущностей, полноценное сопоставление ошибок с отдельными полями, управление несохранёнными черновиками при уходе со страницы, проверка карты в доступной сети и пользовательское испытание на инженерах. Проектные роли и доступ к закрытым данным зависят от реализации RBAC на бэкенде. Наличие обновлённого интерфейса не подтверждает реальный спрос, сетевые условия или готовность всей конкурсной системы.
