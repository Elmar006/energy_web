## Проверки и предметное обоснование

- [Аудит конкурсного ТЗ](commission/TASK_FIT_AUDIT.md): требование → реализация → доказательство → граница вывода.
- [Методика эксперимента](commission/REPORT.md): входы, показатели, сравнение и повтор запуска.
- [Вычислительные и платформенные проверки](evidence/task-fit-2026-10-01/VERIFICATION.md): команды, версии, SHA и результаты.
- [Production-проверки](evidence/production-2026-09-30/VERIFICATION.md): разделение ролей и восстановление БД на зафиксированном стенде.

- [Проверка README и знака](evidence/readme-2026-10-01/VERIFICATION.md): текущие снимки, сборка, UI-тесты и хеши презентационных файлов.

`evidence/` хранит протоколы и результаты; `evidence/ui/` — снимки проверенных интерфейсов; `evidence/benchmarks/legacy/` — прежние версии эксперимента. Регрессионный географический пример расположен в `examples/regression/monaco/` и не участвует в автоматическом запуске приложения. Текущая презентация продукта — [корневой README](../README.md).

## Правила сопровождения

1. Изменение публичного поля сопровождается обновлением OpenAPI, примера и handoff; совместимость `/api/v1` проверяется тестами.
2. Изменение вычислительного кода требует нового SHA, протокола и файла результата. Исторический lock не переписывается.
3. Статус задания, математическая допустимость и сервисная приёмка показываются отдельно. `observed`, `derived`, `assumed` сохраняются после преобразования.
4. Для измерения фиксируются вход, версии, seed и условия стенда. Секреты и операторские выгрузки не добавляются в Git.
